# EscapeAI — חדר בריחה מבוסס בינה מלאכותית

**EscapeAI** הוא משחק חדר בריחה אינטראקטיבי הכולל חמישה חדרים, שרת Python וממשק משתמש ב־React. השחקן פותר חידות היגיון, סדרות מספרים וקודים, ומודל AI בודק תשובות חופשיות ומחזיר משוב.

## תכונות עיקריות

- חמישה חדרי חידות ברצף ומסך ניצחון בסיום.
- בדיקת תשובות באמצעות AI עם פלט מובנה.
- מעקב אחר מספר ניסיונות, ניקוד ורמזים לאחר ניסיונות שגויים חוזרים.
- ניהול זרימת המשחק באמצעות LangGraph ואפשרות לניטור ולהערכה באמצעות LangSmith.

## טכנולוגיות

| רכיב | טכנולוגיות |
| --- | --- |
| צד לקוח (Frontend) | React, TypeScript, Vite, CSS |
| צד שרת (Backend) | Python, FastAPI, Uvicorn |
| בינה מלאכותית | LangChain, OpenAI (`gpt-4o-mini`) |
| ניהול זרימת המשחק | LangGraph |
| ניטור והערכת מודל | LangSmith (אם הוגדר) |

## איך המשחק עובד?

1. השחקן מתחיל משחק חדש ונוצר מזהה סשן.
2. השרת מחזיר את החידה של החדר הנוכחי.
3. השחקן מזין תשובה חופשית.
4. בודק התשובות מעריך את התשובה ומחזיר משוב מובנה.
5. תשובה שגויה מגדילה את מספר הניסיונות; לאחר מספר ניסיונות שגויים עשוי להופיע רמז.
6. תשובה נכונה פותחת את החדר הבא. פתרון החדר החמישי מסיים את המשחק.

> **חשוב:** קבלת רמז אינה פותחת את החדר אוטומטית. כדי להתקדם יש להזין תשובה נכונה.

## שימוש ב־LangSmith
הערכה אוטומטית ושיפור פרומפט באמצעות LangSmith
מטרת הניסוי
בפרויקט EscapeAI ביצענו הערכה אוטומטית של מנגנון בדיקת התשובות באמצעות LangSmith, במטרה לשפר את דיוק המודל בזיהוי תשובות נכונות, שגויות וחלקיות.
גרסה ראשונה — Before
בגרסה הראשונה הפרומפט כלל הוראות כלליות לקבל תשובות בעלות משמעות שקולה ולדחות תשובות שגויות או חלקיות.

עם זאת, לא הוגדר במפורש כיצד יש לבדוק קודים מספריים המורכבים ממספר ספרות, או כיצד להתמודד עם תשובות המכילות כמה אפשרויות.

תוצאות הניסוי: 79% דיוק — 21 מתוך 27 בדיקות הצליחו.
גרסה משופרת — After
בעקבות זיהוי שגיאות בגרסה הראשונה, שיפרנו את הפרומפט והוספנו הוראות מפורשות:
- קבלת תשובה אחת נכונה גם כאשר היא מנוסחת בחוסר ביטחון, למשל אולי 48.
- דחיית תשובות המכילות כמה אפשרויות, למשל 48 או 50.
- זיהוי מספרים הכתובים במילים, למשל ארבעים ושמונה במקום 48.
- זיהוי קודים המשלבים ספרות ומילים, למשל אחד שלוש 4 שניים במקום 1342.
- בדיקה שכל הספרות בקוד מופיעות בסדר הנכון, ללא השמטות.
תוצאות הניסוי: 100% דיוק — 27 מתוך 27 בדיקות הצליחו.

השיפור הכולל: 21 נקודות אחוז.
תובנה מתוך ניתוח Trace
במהלך ניתוח ה־Traces ב־LangSmith זיהינו שגיאה בגרסת Before.

התשובה הנכונה לחידה הייתה 1342, אך השחקן הזין:

אחד שלוש ארבע

תשובה זו מייצגת את הרצף 134 בלבד, ולכן היא חלקית וחסרה בה הספרה האחרונה.

למרות זאת, המודל החזיר:
is_correct = True



בעוד שהתוצאה הצפויה הייתה:
is_correct = False



ב־LangSmith התקבל עבור הבדיקה ציון accuracy = 0.

בגרסת After הוספנו לפרומפט הוראה מפורשת:
For a multi-digit ACCESS CODE,
the order and number of digits must match exactly.


## התקנה והרצה

### דרישות מקדימות

- Python 3.12 או גרסה תואמת.
- Node.js ו־npm.
- מפתח API של OpenAI.

### שלב 1 — הרצת השרת

פתחו טרמינל בתיקייה הראשית של הפרויקט:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

אם לא קיים `requirements.txt`, יש להתקין את הספריות שבהן הקוד משתמש, למשל `fastapi`, `uvicorn`, `python-dotenv`, `langchain-openai` ו־`langgraph`.

צרו קובץ `.env` בתיקייה הראשית:

```env
OPENAI_API_KEY=your_openai_api_key_here
```

יש לוודא שמשתני הסביבה נטענים **לפני** יצירת אובייקט `ChatOpenAI` בקובץ בודק התשובות:

```python
from pathlib import Path
from dotenv import load_dotenv

load_dotenv(Path(__file__).resolve().parent / ".env")
```

הפעילו את השרת:

```powershell
python -m uvicorn api:app --reload
```

### שלב 2 — הרצת צד הלקוח

פתחו טרמינל נוסף:

```powershell
cd frontend
npm install
npm run dev
```

פתחו בדפדפן את הכתובת המקומית ש־Vite מציג. ודאו שכתובת ה־API המוגדרת בצד הלקוח תואמת לכתובת של שרת FastAPI.
